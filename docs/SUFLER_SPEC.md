# Проект: AI-суфлёр для технических собеседований (macOS) — v2

## Цель
Десктопное приложение под macOS (Apple Silicon), которое:
1. По хоткею **и** по кнопке в оверлее делает скриншот экрана и отправляет в Claude.
2. Позволяет вручную ввести вопрос текстом.
3. Слушает микрофон и распознаёт речь в реальном времени (русский + английский, код-свитчинг).
4. Хранит rolling-контекст разговора (последние 30–60 сек), а не только последний вопрос.
5. Показывает краткую подсказку в полупрозрачном незаметном оверлее поверх всех окон.

Назначение: антипаник-суфлёр на теоретических вопросах техсобеса. НЕ для списывания live-coding.

## Стек
- **Язык:** Python 3.11+
- **GUI/оверлей:** PyQt6 (прозрачное frameless окно, always-on-top)
- **Захват микрофона:** `sounddevice`
- **STT:** на Apple Silicon — **whisper.cpp** (Metal-ускорение живое) или **MLX Whisper** (нативно под Apple).
  НЕ faster-whisper: его бэкенд CTranslate2 на Mac упирается в CPU, Metal там нет.
  Архитектура должна позволять заменить STT-движок (whisper.cpp / MLX / Deepgram) сменой одного модуля.
- **Скриншот:** нативный `screencapture` (subprocess) + fallback `mss`.
- **Хоткей:** `pynput` (глобальные хоткеи).
- **LLM:** Anthropic Claude API (`anthropic` SDK), мультимодальный запрос (текст + image/base64 PNG).
- **Конфиг:** `.env` (ANTHROPIC_API_KEY, STT-движок, модель, хоткеи, язык ответа, режим coach/answer).

## Ключевые требования к реализации

### STT (audio/stt.py) + задержки
- Абстрактный базовый класс `STTEngine`.
- Реализация на **whisper.cpp** (через биндинг/CLI server) или **MLX Whisper**. Автоопределение языка.
- Стаб `DeepgramEngine` (websocket) — интерфейс заложить, реализацию позже.
- **Задержки (критично для собеса):**
  - быстрый partial buffer 1–1.5 сек (черновое распознавание на лету);
  - финализация фразы по паузе 600–900 мс;
  - кнопка/хоткей "ответить по последним 15–25 сек речи".
- Буфер 2–4 сек как раньше — НЕ годится, слишком медленно.

### Rolling context (core/context.py)
- Хранить НЕ только `last_question`, а скользящий контекст:
  - последние 30–60 секунд распознанной речи;
  - последний уверенно распознанный вопрос;
  - последний ручной скриншот.
- Цель: отвечать на "а чем отличается от предыдущего варианта?" — с учётом истории.
- Контекст уходит в Claude вместе с текущим запросом.

### Скриншот (vision/screenshot.py)
- `grab_screen(region=None) -> base64 str` через `screencapture -x`.
- Захват области (`-R x,y,w,h`).
- **Перед захватом прятать оверлей** (`hide()` + `processEvents()` + ~0.15с пауза), потом `show()` — чтобы суфлёр не попал в кадр.

### LLM (llm/claude.py) + режимы
- Два режима (переключаемые):
  - **answer:** краткий готовый ответ, 2–4 пункта телеграфно.
  - **coach:** НЕ готовый ответ, а 3 тезиса-опоры, чтобы человек говорил сам (не "NPC с задержкой пинга").
- Системный промпт: суфлёр уровня senior. Отвечать на русском, термины оставлять на английском.
- Мультимодальный запрос: `{type:"text"}` + `{type:"image", source: base64 PNG}` + rolling context.
- Стриминг ответа токенами в оверлей.
- Модель в конфиге.

### Оверлей (ui/overlay.py) + stealth UX
- Frameless, `WindowStaysOnTopHint`, полупрозрачный, маленький шрифт, сбоку.
- Поля: распознанный вопрос (сверху, мелко) + ответ (снизу, стрим).
- **Три входа в одну точку `on_capture`:** хоткей, кнопка "📸 Скрин", ручной ввод текста.
- Ручной ввод текста — ПОСТОЯННАЯ фича, не времянка (быстрее напечатать, чем ждать STT).
- **Stealth-фичи (обязательно):**
  - opacity hotkeys: 20/40/70%;
  - click-through mode (клики проходят сквозь оверлей);
  - compact mode (только ответ);
  - auto-hide через 10–15 сек;
  - **panic hotkey: мгновенно скрыть всё** (на случай "расшарьте весь экран").

### Триггеры (core/controller.py)
- Хоткей (pynput) → `on_capture`.
- Кнопка оверлея → `on_capture` (общий метод).
- Ручной ввод → отправка без скрина.
- Хоткей "ответь по последним N сек" → берёт rolling context, без скрина.
- `on_capture`: спрятать оверлей → скрин → показать → (скрин + context) в Claude → стрим в оверлей.

## macOS-специфика (обязательно)
- **Права** для приложения/терминала, откуда запуск:
  - Микрофон (Privacy → Microphone)
  - Запись экрана (Privacy → Screen Recording) — иначе скрин чёрный
  - Accessibility — для глобальных хоткеев pynput
- Apple Silicon: whisper.cpp с Metal или mlx-whisper нативно. README с инструкцией сборки.
- PyQt6 прозрачность на Mac капризна — проверить `WA_TranslucentBackground`, click-through через `WA_TransparentForMouseEvents`.

## Порядок сборки (для Claude Code) — ПЕРЕСТАВЛЕН
Сначала то, что даёт пользу без аудио-ада. STT и loopback — позже.
```
MVP:
1. Overlay (PyQt6, stealth-контролы, замокать ответ статикой)
2. Screenshot → Claude (screencapture + claude.py, текст+картинка, стрим)
3. Hotkey (pynput, + panic hotkey)
4. Ручной ввод текста
--- здесь уже рабочий полезный инструмент ---
5. STT (whisper.cpp/MLX, partial buffer + финализация по паузе)
6. Rolling context (буфер 30–60 сек)
7. Loopback audio (захват звука собеседника)
```
Обоснование: screenshot + Claude + overlay уже полезны на собесе с задачей/вопросом на экране.
STT превращает проект в филиал ада с буферами/драйверами/правами — делать на готовой основе.

## Loopback (этап 7, не раньше)
- Захват звука собеседника: **BlackHole** (проще) как старт.
- ScreenCaptureKit / CoreAudio Taps — красивее и официально покрывает screen+audio, но больнее. Позже.
- Причина не тащить рано: через голый микро — эхо, шумы, Zoom-компрессия, фоновый шум.

## Замечания
- НИКАКИХ API-ключей в коде — только `.env`.
- Локальный whisper.cpp/MLX → звук не уходит наружу (приватность для NDA-собесов).
- Ответы суфлёра короткие — читать глазами за 2–3 сек, не зачитывать.
- Coach-режим по умолчанию предпочтительнее: говоришь сам, не выглядишь читающим.
